# 10 · MVP 开发拆解

## 1. 开发顺序（先跑通，再做 UI）

```
1. 建立产品骨架
2. 建立真实数据库
3. 接入 DeepSeek API
4. 实现知识共创
5. 实现知识入库
6. 实现知识关联
7. 实现知识调用
8. 实现复习和出题
9. 实现掌握状态
10. 实现演化和合并
11. 再完善 UI / 视觉
```

## 2. 里程碑拆解

| 阶段 | 内容 | 交付标准 |
| --- | --- | --- |
| M1 骨架 | monorepo + Git + README + .env | 项目可初始化、可提交 |
| M2 数据 | Prisma Schema + 迁移 | 所有实体可建表 |
| M3 AI | DeepSeek 统一封装 | 对话/JSON 抽取可用 |
| M4 共创 | discuss + confirm + 入库 | 闭环 A 跑通 |
| M5 关系 | 关系发现 + 图谱 | 闭环 B 跑通 |
| M6 调用 | Ask 知识调用 | 闭环 C 跑通 |
| M7 复习 | 出题 + 评估 + 掌握度 | 闭环 D 跑通 |
| M8 演化合并 | 版本 + 合并 + 画像推荐 | 闭环 E/F 跑通 |
| M9 UI | Web 前端全部页面 | 界面可用 |

## 3. 六个核心闭环验收（需求第 41 条）

- **知识共创闭环**：输入 → 讨论 → 共识 → 用户确认 → 入库
- **知识关联闭环**：新知识 → 找旧知识 → 建立关系 → 展示关系
- **知识调用闭环**：用户问题 → 找到历史知识 → 结合当前问题回答
- **复习闭环**：生成题目 → 用户作答 → AI 评估 → 更新掌握状态 → 安排后续复习
- **演化闭环**：新信息 → 更新旧知识 → 保留历史 → 当前状态变化
- **合并闭环**：发现重复 → 建议合并 → 用户确认 → 新知识生成

## 4. API 优先清单

创建/修改/查询知识、AI 知识共创、建立关系、查询相关知识、AI 问答、生成题目、提交答案、更新掌握度、查询复习计划、知识合并、知识演化，全部通过后端 API 完成。

Web 与未来 Mobile 通过统一后端 API 共享同一套数据和 AI 能力。

## 5. 暂不做（第一版边界）

- 团队协作、共享知识库、企业功能（单用户私有产品）
- 复杂引用系统（数据结构预留，界面简化）
- 完整 Obsidian 双向同步（预留导出接口）
- 复杂科学间隔算法（先用简单版本）
- 移动端 App（架构预留，第二阶段）

## 6. 模块化边界（避免塞进页面代码）

AI Service、Knowledge Service、Relation Service、User Profile Service、Learning/Coach Service、Recall/Search Service、Scheduler 各自独立，未来换模型、加移动端、改算法无需大面积重写。
