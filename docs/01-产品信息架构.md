# 01 · 产品信息架构（IA）

## 1. 产品定位

一个私人 AI 知识教练。核心目标：让一个真正想学习、想进步的人，经过长期使用后，明显感觉自己越来越懂，并且越来越容易调用过去积累的知识。

关键词：**长期陪伴、知识沉淀、认知检测、主动教练**。

## 2. 信息组织的核心理念

产品不围绕「笔记」组织，围绕「知识对象（Knowledge）」组织。一个知识对象是经过 AI 与用户共创、确认后的结构化结论，它拥有类型、分类、关系、来源、版本、掌握状态等完整属性。

三层信息模型（借鉴 Karpathy LLM Wiki 并扩展）：

```
原始输入 / 来源（raw，内部保留）
   ↓ LLM 编译 + 用户共创确认
结构化知识（Knowledge，用户主要看到）
   ↓ 关系累积 + 认知建模
知识网络 + 用户认知画像（长期资产）
```

## 3. 顶层信息分区

| 分区 | 内容 | 用户视角 |
| --- | --- | --- |
| 记录 | 输入入口、共创讨论 | 我学到了什么 |
| 知识 | 结构化知识库 | 我积累了哪些知识 |
| 网络 | 知识关系图谱 | 我的知识如何连成体系 |
| 问 AI | 知识调用问答 | 过去的知识如何帮助现在的我 |
| 复习 | 出题、掌握度、复习计划 | 我真正掌握了吗 |
| 画像 | 用户认知模型、学习推荐 | AI 越来越懂我 |

## 4. 导航结构

```
首页（今日状态 + 入口）
├── 记录 / 共创（输入 → 讨论 → 入库）
├── 知识库（列表 / 搜索 / 筛选）
│   └── 知识详情页
├── 知识网络（图谱）
├── 问 AI
├── 复习
│   ├── 复习计划
│   └── 复习会话（做题）
└── 我的画像（只读展示 + 学习推荐）
```

## 5. 核心信息流

```
用户输入 → 共创讨论 → 共识 → 确认入库 → 结构化知识
结构化知识 → 关系发现 → 知识网络 → 断层分析
用户提问 → 知识调用 → 引用历史知识回答
系统出题 → 用户作答 → 掌握度更新 → 复习调度
新信息 → 知识演化 / 合并 → 版本历史保留
```

## 6. 设计原则

- 用户主要看到「最终知识」，原始输入和讨论过程内部保留、界面不强调。
- 分类体系由 AI 自动生长，用户不被迫维护。
- 知识会变化，更新、合并、过时、归档都支持，尽量不覆盖历史。
- 掌握度多维（认知 / 回忆 / 理解 / 关联 / 应用 / 稳定性），界面可简化展示。
