# 04 · 数据库设计

数据库默认 SQLite（本地零配置），通过 Prisma ORM 管理，可无缝切换 Postgres。

## 1. 实体清单（需求第 35 条）

`User`、`Knowledge`、`KnowledgeRelation`、`KnowledgeSource`、`KnowledgeVersion`、`Category`、`Tag`、`UserProfile`、`UserKnowledgeState`、`ReviewSession`、`Question`、`QuestionAttempt`、`LearningRecommendation`、`KnowledgeGap`、`ConversationSession`。

核心数据：`Knowledge + KnowledgeRelation + UserKnowledgeState`。

## 2. 实体关系总览

```
User 1──N Knowledge
User 1──1 UserProfile
User 1──N UserKnowledgeState ──N──1 Knowledge
Knowledge 1──N KnowledgeSource
Knowledge 1──N KnowledgeVersion
Knowledge N──N Knowledge (via KnowledgeRelation, from/to)
Knowledge N──N Tag
Knowledge 1──N Category（树形，parentId 自关联）
User 1──N ReviewSession 1──N Question 1──N QuestionAttempt
User 1──N LearningRecommendation
User 1──N KnowledgeGap
User 1──N ConversationSession
```

## 3. 核心表字段

### User
`id`、`email`、`username`、`passwordHash`、时间戳。

### Knowledge（知识对象，核心）
`id`、`title`、`coreConclusion`（核心结论）、`briefExplanation`（简洁解释）、`detailExplanation`（详细解释）、`example`、`type`（知识类型）、`status`（active/outdated/archived/deleted）、`confidence`（可信度）、`isOutdated`、`categoryId`、`userId`、时间戳。

### KnowledgeRelation（知识关系）
`id`、`type`（related/prerequisite/hyponym/hypernym/causal/contrast/application/conflict/evolution/bridge）、`fromId`、`toId`、`reason`（为什么）、`confidence`、`userId`。唯一约束 `(fromId, toId, type)`。

### KnowledgeSource（来源）
`id`、`type`（抖音/微信/客户交流/书籍/文章/网络/AI 讨论/自己总结/项目经验…）、`detail`、`occurredAt`（来源时间）、`note`、`knowledgeId`。

### KnowledgeVersion（历史版本）
`id`、`knowledgeId`、`version`、`title`、`coreConclusion`、`detailExplanation`、`changeReason`（变化原因）、`sourceNote`、`createdAt`。

### Category（分类，树形）
`id`、`name`、`parentId`（自关联）。

### Tag
`id`、`name`（唯一）。

### UserProfile（用户画像）
`id`、`userId`（唯一）、`occupation`、`workDomain`、`currentFocus`、`primaryKnowledgeAreas`(JSON)、`commonScenarios`(JSON)、`technicalDepth`、`businessLevel`、`interests`(JSON)、`learningGoals`(JSON)、`deepDiveAreas`(JSON)、`shallowAreas`(JSON)、`commonMistakes`(JSON)、`weakDirections`(JSON)。

### UserKnowledgeState（用户掌握状态，核心）
`id`、`userId`、`knowledgeId`、`awareness`(认知)、`recall`(回忆)、`understanding`(理解)、`association`(关联)、`application`(应用)、`stability`(稳定性)、`recommendedDepth`（understand/apply/master/skip）、`lastReviewedAt`、`nextReviewAt`、`reviewCount`、`forgetRisk`。唯一约束 `(userId, knowledgeId)`。

### ReviewSession / Question / QuestionAttempt（复习与题目）
- `ReviewSession`：`type`、`status`、`knowledgeIds`(JSON)。
- `Question`：`type`（choice/recall/understanding/comparison/counterexample/application/association/open）、`prompt`、`options`(JSON)、`answer`、`difficulty`。
- `QuestionAttempt`：`answer`、`isCorrect`、`score`、`feedback`、`errorType`（forget/confusion/missing_relation/missing_prerequisite/misunderstand/misapply）。

### LearningRecommendation（学习推荐）
`type`（gap/review/study/bridge）、`title`、`detail`、`knowledgeIds`(JSON)、`status`（pending/accepted/dismissed）。

### KnowledgeGap（知识断层）
`fromKnowledgeId`、`toKnowledgeId`、`gapDescription`、`recommended`（是否值得学）、`reason`、`status`（open/resolved/ignored）。

### ConversationSession（对话会话，非知识主体）
`mode`（cocreate/ask/review）、`status`、`title`、`rawContent`、`messages`(JSON 对话流)。

## 4. 设计要点

- 用字符串表示枚举值（SQLite 不支持原生 enum，也便于未来扩展）。
- 知识类型、关系类型、来源类型、错题类型都设计为可扩展字符串。
- JSON 字段用于画像、题目选项、会话消息等灵活结构。
- 版本与状态字段保证「不覆盖历史」。
