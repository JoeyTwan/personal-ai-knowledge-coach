> 验收对象：个人 AI 知识教练 · 9 个核心闭环
> 验收方式：第一轮代码/prompt 静态审查 + 第二轮真实 DeepSeek 端到端实测
> 验收时间：2026-09-04
> 测试脚本：`scripts/acceptance_test.py`（关系/画像/断层/问答/复习）、`scripts/acceptance_test_merge.py`（合并/演化）

## 一、总结论（先行）

| 闭环 | 结论 | 一句话 |
| --- | --- | --- |
| 1 知识共创 | ✅ 合格（1 缺陷） | AI 会追问纠错、感知销售身份、调整深度，但自动分类没落地 |
| 2 知识关联 | ✅ 合格（1 专项缺陷） | 关系发现质量高，但「知识桥梁」从未触发 |
| 3 知识调用 | ✅ 合格（1 隐患） | 检索准、区分「已有/补充」好，但检索非语义 |
| 4 复习出题 | ⚠️ 部分合格 | 出题评估正常，但题型硬编码轮换 |
| 5 掌握度评估 | ⚠️ 部分合格 | 能判对错，但「真的会 vs 看过」无判别 |
| 6 知识断层 | ⚠️ 部分合格 | 断层发现质量高，但推荐「一刀切」全值得学 |
| 7 知识合并 | ✅ 基本可用 | 能合并，但重复检测有不确定性 |
| 8 知识演化 | ❌ 失败 | 递进信息生成重复知识，未识别演化 |
| 9 用户画像 | ⚠️ 部分合格 | 技术深度/商业水平推断准，但职业身份没推断出 |

**三个专项能力（用户特别点名）**：

| 专项 | 结论 |
| --- | --- |
| 知识桥梁 | ❌ 未触发（7 条关系边中无 bridge，数据结构也承载不了「缺失的 C」） |
| 职业差异深度 | ⚠️ 半生效（共创环节优秀，断层环节失效） |
| 真的会 vs 看过 | ❌ 未实现（能识别误解，但无「背诵 vs 理解」判别，错题归因不闭环） |

## 三、逐闭环实测记录

### 用例 1 · 知识共创

| 字段 | 内容 |
| --- | --- |
| **输入** | 用户：「我今天学了视觉 Transformer，优势主要是它可以看到整个图像」 |
| **真实 AI 行为** | 连续 6 轮高质量讨论：① 追问「看到整个图像」的含义，区分全局建模/注意力覆盖两种理解；② 纠正「全局关系是天生还是训练出来」的误区；③ 追问「全局建模带来什么实际优势」，引导到遮挡识别、长距离依赖场景；④ 纠正「CNN 也能捕捉长距离依赖，只是隐式渐进」；⑤ 感知销售身份后明确「不需要数学细节，但要能应对客户追问」，并问要「原理认知」还是「销售话术」；⑥ 列出 4 点框架征求意见。 |
| **共识形成** | 用户明确说「确认可以入库」后，AI 正确输出 `<CONSENSUS>` 标记，草稿质量高（标题/结论/详解/示例/类型/标签齐全）。 |
| **入库后** | 知识成功入库，但 `categoryId = None`。 |
| **问题** | ① 自动分类未落地（`classifySystem` 是死代码，P0）；② 共识标记触发时机偏保守，AI 会先文字列框架+口头确认，用户需再说一次「入库」才输出标记，中间态前端无兜底（P2）。 |
| **严重程度** | P0（分类）、P2（标记触发） |
| **修改建议** | ① `confirmKnowledge` 入库前调用 `classifySystem` 生成 `categoryPath`；② 前端对「AI 文字总结但 draft 为 null」的中间态提供「手动生成草稿」入口。 |

### 用例 3 · 知识调用（Ask）

| 字段 | 内容 |
| --- | --- |
| **输入** | 「客户要买 AI 服务器做推理，我该怎么帮他考虑显存和算力的配置？」 |

| **问题** | 检索是纯 `contains` 关键词匹配（无分词、非语义，P0），本次问题恰好含「显存」「算力」等精确关键词才命中，语义相近但措辞不同的提问会漏召回。 |
| **严重程度** | P0（检索）、（区分标注本次表现好，降级） |
| **修改建议** | 引入分词（开源 `nodejieba`）+ 向量检索，做「关键词 + 向量」混合召回。 |

### 用例 4/5 · 复习出题 + 掌握度评估（含「真的会 vs 看过」专项）

| 字段 | 内容 |
| --- | --- |
| **输入** | 开启复习会话，连续取 3 题并作答 |
| **真实 AI 行为** | 3 题题型全部是 `recall`（难度 1），因为 `reviewCount=0`。评估能正确判对错：答「Transformer 自注意力」给 ViT 题判错（errorType=missing_relation）、给算力题判错（errorType=misunderstand）、给 Transformer 题判对（score 0.7）。 |
| **问题** | ① 题型硬编码轮换（`chooseQuestionType` 按 reviewCount 机械递增，不看掌握状态、答错不降难度，P1）；② `errorType` 存了但不驱动下一次出题类型，错题归因闭环断裂（P0）；③ 无「背诵 vs 理解」判别机制，choice/辨析题从不调度（P0）。 |
| **严重程度** | P0（归因闭环、真会vs看过）、P1（题型轮换） |
| **修改建议** | ① `chooseQuestionType` 改读 `state` 各维度 + 上次答题结果，答错降难度；② `errorType` 驱动下一次出题（混淆→对比题、断层→推荐、误用→场景题）；③ 引入辨析题/反例题判别「真理解」。 |

### 用例 6 · 知识断层（含「职业差异深度」专项）

| 字段 | 内容 |
| --- | --- |
| **输入** | 调用断层发现，知识库 5 条 AI/硬件相关知识 |
| **真实 AI 行为** | 发现 3 个断层，reason 都结合了画像（「提升商业决策能力」等）。但**全部 `recommended: True`**，包括「自注意力数学原理 Q/K/V 矩阵运算」这种销售本不需要深入的数学断层。 |
| **问题** | ① 断层推荐「一刀切」，未体现原则 6「不是什么都值得学」（P0）；② 根因：`getProfileText` 未注入 `shallowAreas`（画像推断的 shallowAreas 也为空），缺「哪些领域只需了解」的依据（P1）。 |
| **严重程度** | P0（职业深度在断层失效） |
| **修改建议** | ① `getProfileText` 注入 shallowAreas/deepDiveAreas/commonMistakes/weakDirections；② 断层 prompt 增加「对销售无需深入的纯数学断层，明确 recommended=false 并说明原因」。 |

### 用例 7 · 知识合并

| 字段 | 内容 |
| --- | --- |
| **输入** | 录入两条几乎相同的「昇腾 310B 算力 20 TOPS」知识 |
| **真实 AI 行为** | 重复检测正确识别（reason「内容完全一致」），合并执行正确（合并成一条，新知识标题/结论合理，旧知识归档 + evolution 关系）。 |
| **问题** | ① 重复检测**有不确定性**：同一批「液冷」递进数据，第一次 detect 返回空，第二次才检测到（LLM 非确定性，P1）；② 合并后新知识不重建与其它知识的关系（P1）。 |
| **严重程度** | P1 |
| **修改建议** | ① 增加向量相似度做确定性兜底，LLM 只做复核；② 合并后调用 `discoverRelations`。 |

### 用例 8 · 知识演化（需求案例 E 专项）

| 字段 | 内容 |
| --- | --- |
| **输入** | 录入 3 条「某厂商液冷能力」递进信息（7月听闻→8月客户反馈→9月项目验证） |

| **修改建议** | 入库前增加一步：AI 判断当前共识是否是对某条已有知识的更新/增强，若是则更新旧知识 + 记录版本 + 提升 confidence + 追加来源，否则新建。 |

## 四、缺陷汇总（最终版）

### P0（核心能力缺失，5 个，均已实测确认）

| # | 缺陷 | 实测证据 |
| --- | --- | --- |
| P0-1 | 自动分类未落地 | 入库知识 `categoryId=None` |
| P0-2 | 检索非语义 | 静态确认 `contains` 匹配，本次关键词巧合命中 |
| P0-3 | 知识桥梁不可用 | 7 条关系边中无 bridge |
| P0-4 | 知识演化未实现 | 3 条递进信息生成 3 条独立知识 |
| P0-5 | 「真的会 vs 看过」无判别 | errorType 存而不用，无辨析题 |

### P1（重要缺陷，6 个）

| # | 缺陷 | 实测证据 |
| --- | --- | --- |
| P1-1 | 题型硬编码轮换 | 3 题全 recall，答错不降难度 |
| P1-2 | 关系标题精确匹配 | 静态确认，本次未暴露 |
| P1-3 | 画像关键字段未注入 prompt | 断层推荐一刀切，shallowAreas 空 |
| P1-4 | 画像无行为数据源 | occupation 未推断出销售 |
| P1-5 | 重复检测不确定性 | 同批数据两次 detect 结果不同 |
| P1-6 | 合并后不重建关系 | 静态确认 |

### P2（体验/健壮性，6 个）

| # | 缺陷 |
| --- | --- |
| P2-1 | 共识标记触发时机保守，中间态前端无兜底 |
| P2-2 | `extractKnowledgeSystem` 死代码 |
| P2-3 | 无匹配时退回最近 10 条任意知识 |
| P2-4 | 8 类题型只调度 5 类 |
| P2-5 | 关系发现/断层/画像/推荐均手动触发或失败静默 |
| P2-6 | 共创无「至少追问 N 轮」硬约束（实测 AI 追问充分，风险较低） |

## 五、下一步建议

1. **修复优先级 P0 → P1 → P2**。P0 全部是「产品理念核心能力缺失」，建议先修。
2. P0 修复顺序建议：P0-4（演化，最伤数据质量）→ P0-1（分类）→ P0-2（检索）→ P0-3（桥梁）→ P0-5（真会vs看过，涉及出题/评估/复习多处）。
3. 本轮验收结论已覆盖「9 闭环 + 3 专项」，等你确认修复范围后，我按优先级逐项实现。
