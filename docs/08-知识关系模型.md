# 08 · 知识关系模型

知识关系是产品核心能力，AI 自动发现并建立。

## 1. 关系类型

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| related | 相关 | A 与 B 有关系 |
| prerequisite | 前置 | 掌握 A 后更容易理解 B |
| hyponym / hypernym | 下位 / 上位 | A 是 B 的子概念 / 父概念 |
| causal | 因果 | A 导致 B |
| contrast | 对比 | A 与 B 有明显差异 |
| application | 应用 | A 可用于 B |
| conflict | 冲突 | A 与 B 存在矛盾或不同观点 |
| evolution | 演化 | A 是旧版本，B 是更新版本 |
| source | 来源关系 | A 的信息来自某来源 |
| bridge | 知识桥梁 | A 和 B 之间存在重要中间知识 C |

## 2. 数据结构

```ts
interface KnowledgeRelation {
  id: string
  type: RelationType
  fromId: string
  toId: string
  reason?: string    // 为什么建立这个关系
  confidence?: number
}
```

唯一约束：`(fromId, toId, type)` 防止重复关系。

## 3. 知识桥梁（关键能力）

用户知道 A 也知道 B，但缺少连接 A 和 B 的 C。系统识别这种「桥梁」关系，帮助发现知识断层。

## 4. 知识断层分析

```
用户已有知识 A → B，中间缺失重要知识 C。
系统判断：对当前用户而言 C 是否值得学习。
程序员：A → B → C → D 需深入全部。
销售：A → D，中间只需知道概念关系。
```

断层推荐必须个性化，不能机械补齐。

## 5. 关系发现流程

```
新知识入库
  → 检索已有知识（关键词 + 语义 + 分类）
  → 调用 LLM 判断候选关系（前置/因果/对比/应用/冲突/演化/桥梁）
  → 生成关系建议
  → 写入 KnowledgeRelation
  → 更新知识网络
```

## 6. 冲突与演化

- **冲突**：发现两条知识观点矛盾时，建立 conflict 关系并提示用户。
- **演化**：新信息更新旧知识时，建立 evolution 关系，保留历史版本。
