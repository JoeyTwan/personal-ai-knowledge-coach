# 07 · 用户掌握度模型

不只用「掌握 / 不掌握」二元判断，维护多维内部状态。

## 1. 六个维度（内部维护，界面可简化）

| 维度 | 含义 |
| --- | --- |
| awareness（认知） | 是否接触、知道这个概念存在 |
| recall（回忆） | 不看资料能否回忆起 |
| understanding（理解） | 是否理解原理与逻辑 |
| association（关联） | 能否与其他知识建立联系 |
| application（应用） | 能否迁移到真实场景 |
| stability（稳定性） | 掌握的牢固程度 |

每维取值 0-1（或 0-100）。

## 2. 示例

```
Transformer
认知：高  回忆：高  理解：高  关联：中  应用：中  稳定性：中
```

## 3. 补充字段

- `recommendedDepth`：推荐掌握深度（understand / apply / master / skip），由用户角色与目标决定。
- `lastReviewedAt`：上次复习时间。
- `nextReviewAt`：下次推荐复习时间。
- `reviewCount`：复习次数。
- `forgetRisk`：遗忘风险。

## 4. 掌握度的证据来源

不能因「收录了知识」就认定「已掌握」。掌握度来自：

- 回忆题、解释题、理解题、对比题、反例题、应用题、开放题、选择题的作答结果。
- 主动提问时的调用表现。
- 长期未复习导致的遗忘风险上升。

## 5. 更新规则（初版，简单可靠）

```
新知识入库：各维度初始为低值（如 0.2），安排初次检测。
答对回忆题：recall 上升；答对理解题：understanding 上升；答对应用题：application 上升。
答错：对应维度下降，记录错题归因，缩短下次复习间隔。
长期未复习：stability 下降，forgetRisk 上升。
```

## 6. 个性化深度（结合用户画像）

```
程序员：Transformer 需深入 Attention 计算过程。
销售：只需理解 Transformer 是什么、解决什么问题、为何需要算力、与 GPU/AI 服务器的关系、适用业务场景。
```

系统维护「世界知识结构完整」的路径，但展示给用户的是「根据身份和目标过滤后的知识路径」。
